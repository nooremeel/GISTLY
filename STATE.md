## Key Architectural Decisions
- **AI Provider:** Google Gemini API, accessed via its official SDK from the backend only (never exposed to frontend).
- **AI Model Choice:** Using `gemini-3.5-flash-lite` — full Flash models cap the free tier at 20 requests/day; Flash-Lite gives 500/day and 15 RPM and suits this short-extraction task (Task 07).
- **AI Failure Handling:** `aiService.generateSummaryAndTags` never throws — returns `{ summary: null, tags: [] }` on any failure, so bookmark creation always succeeds (Task 07). `AddBookmarkForm.jsx` (Task 17) relies on this: no distinct AI-failure branch needed.
- **Bookmark Content Source for AI:** Priority is fetched page text → user `note` → raw `url` string. Capped at 6s / 6000 chars (Task 07).
- **Tag Merging:** User-submitted and AI-generated tags merged, deduped case-insensitively, user casing wins on collision. Near-duplicate tags (e.g. "Node.js" vs "NodeJS") not caught — deferred.
- **Database:** MongoDB + Mongoose. `Bookmark` indexes `user` and compound-indexes `{ user, tags }` for `getGrouped`/`getByTag` (Task 09).
- **DB Connection Pattern:** `backend/config/db.js` exports async `connectDB()`, called once at bootstrap in `server.js`; failure exits the process.
- **Auth (Backend):** JWT sessions, httpOnly `SameSite=Lax` cookie (not localStorage). Passwords hashed with `bcryptjs`, ≥10 salt rounds. 7-day token expiry. Cookie/JWT logic centralized in `utils/generateToken.js`. `secure` flag branches on `NODE_ENV === 'production'` — **confirm this is actually set in the deploy/CI environment.**
- **Password Field Handling:** `User.password` uses `select: false`; `authController.login` opts in via `.select('+password')`.
- **Authorization Pattern:** Every bookmark query filters by `{ _id, user: req.user.id }` in one combined Mongo filter, set via `auth.js` middleware. Aggregation routes scope `$match` by `user: req.user.id` (manually cast to `ObjectId`).
- **Not-Found vs Forbidden:** Bookmark routes return `404` (not `403`) for missing/foreign/malformed-ID cases alike, to avoid existence/ownership leaks (Task 06). Frontend distinguishes these via `err.status` as of Task 15.
- **Mongoose Hook Style:** `pre('validate')`/`pre('save')` hooks written as `async function () {...}` with **no** `next` parameter — mixing async + explicit `next()` throws `TypeError` (Task 06 fix of a Task 05 bug).
- **Mutating Updates Use `.save()`:** `updateBookmark` fetches then `.save()`s (not `findOneAndUpdate`) so `pre('validate')` hooks still run on edits — relied on by `EditBookmarkModal.jsx` (Task 15).
- **Security Middleware:** `helmet`, `morgan`, custom in-place Mongo-injection sanitizer — all in `backend/middleware/security.js`, applied at bootstrap (Task 03).
- **CORS:** `applySecurityMiddleware` in `backend/middleware/security.js` (not `server.js`) owns the `cors()` call. As of Task 18, `origin` is a callback validating the request's `Origin` header against `allowedOrigins`, an array parsed from `CLIENT_ORIGIN` (comma-separated for multiple origins, e.g. staging + prod). Requests with no `Origin` header (curl, server-to-server) are always allowed. Rejected origins throw inside `cors()` and are caught by the generic `errorHandler`, currently surfacing as a 500 rather than a dedicated 403 — see Open Questions.
- **Rate Limiting:** `authLimiter` (15min/max 10, failed-only) on `POST /api/auth/login`; `aiLimiter` (1hr/max 20) on `POST /api/bookmarks`. Both wired as exact-path `app.post(...)` middleware in `app.js`, ahead of router mounts (Task 08). `AddBookmarkForm.jsx` (Task 17) handles the `aiLimiter` 429 case specifically.
- **Error Handling (Backend):** Centralized in `backend/middleware/errorHandler.js` — `notFound` + `errorHandler`, mounted last in `app.js`. Existing controllers still catch/respond locally (not refactored to `next(err)`); `errorHandler.js` is a safety net for anything uncaught, including CORS-rejection errors as of Task 18.
- **Input Validation:** `backend/middleware/validateInput.js` — `validateRegister`, `validateLogin`, `validateBookmarkUrl`, applied as exact-path middleware ahead of router mounts (Task 08). `title` has no dedicated validation (optional free-text). As of Task 18, every form input (`Login.jsx`, `Register.jsx`, `AddBookmarkForm.jsx`, `EditBookmarkModal.jsx`) now has a proper `<label htmlFor>`/`id` pair instead of placeholder-only text.
- **API Style:** REST under `/api/*` prefix.
- **Pagination & Search:** `page`/`limit` on `GET /api/bookmarks`, default limit 12, response `{ data, total, page, pages }`, newest-first. Now supports `?search` query param for case-insensitive substring matches across `title`, `note`, and `url` (added during Redesign Task 11). Consumed by `BookmarkList.jsx`.
- **Aggregation Route Pattern:** `getGrouped`/`getByTag` live in `bookmarkController.js`, registered above `GET /:id` to avoid param-route swallowing (Task 09). `$match` on `user` needs manual `ObjectId` casting.
- **Controller Response Shape:** `getBookmark`, `updateBookmark`, `createBookmark` return flat, unwrapped bookmark objects. Only list endpoints (`getBookmarks`, `getGrouped`, `getByTag`) wrap arrays in `{ data: [...] }`.
- **Testing:** Jest + Supertest (Task 10), `npm test` (`jest --runInBand`), in-memory MongoDB via `mongodb-memory-server` (not a real `MONGODB_URI` test DB). Gemini mocked at the `aiService` module level, never real. No frontend automated tests yet — **Task 19 adds CI for the existing backend suite; frontend tests remain deferred (Task 21 stretch goal).**
- **App/Server Split:** `backend/app.js` exports the configured Express app (no DB connect/listen); `backend/server.js` is the only file calling `validateEnv()`, `connectDB()`, `app.listen()`. Tests/scripts import `app.js` directly.
- **Test Database Strategy:** `mongodb-memory-server`, fresh instance per test run, bypasses `connectDB()` entirely — no `MONGODB_URI` needed for tests. **Relevant for Task 19:** CI environment needs no real MongoDB service/credentials, just the ability to download the `mongod` binary.
- **Mongo Binary MD5 Check:** Disabled (`MONGOMS_MD5_CHECK=0`) in `tests/setup.js` due to local-machine checksum failures (likely antivirus interference). **Open question directly relevant to Task 19** — untested whether GitHub Actions' environment needs this flag at all.
- **AI Mocking in Tests:** `aiService.generateSummaryAndTags` mocked at the module level via `jest.mock('../services/aiService')` in `bookmarks.test.js`, not the underlying SDK client.
- **Frontend State:** React Context for auth (`AuthContext`) and toasts (`ToastContext`); local component state elsewhere. `BookmarkList.jsx` owns the `bookmarks` array (fetch, pagination, in-place update/delete/create, search/tag filter state).
- **Cross-Component State Updates via `forwardRef`/`useImperativeHandle`:** Pattern established in Task 17 for sibling components needing to push state into a component that owns its own state without lifting that state to a shared parent.
- **`AddBookmarkForm` UX Pattern:** Always-mounted (no toggle), holds AI-generated preview for 4s via `setTimeout` before clearing (Task 17).
- **Notifications:** One centralized toast system (`ToastContext` + `Toast.jsx`), `showToast(message, type, duration)`, `type` ∈ `'success' | 'error' | 'info'` (convention, not enforced), default 3.5s auto-dismiss, stacking, click-to-dismiss. Wired into `Login.jsx`, `Register.jsx`, `Home.jsx`, `BookmarkList.jsx`, `EditBookmarkModal.jsx`/`BookmarkCard.jsx`, `AddBookmarkForm.jsx`.
- **Folder/Tag Model:** Tags as a string array on `Bookmark`; folders/collections as a separate string field; aggregation via `$group` (Task 09).
- **Filtering Model:** Search + tag-pill filtering as derived/local view state in `BookmarkList.jsx` (`searchTerm`, `activeTag`, `filteredBookmarks` recomputed every render, no memoization yet). Pure client-side, zero backend involvement (Task 16).
- **Bookmark Title Field:** `title` on `Bookmark` — `String`, trimmed, `default: ''`, optional, user-typed only. No dedicated validation. Wired through `createBookmark`/`updateBookmark`. `BookmarkCard.jsx` falls back to `url || 'Untitled bookmark'`.
- **XSS Note:** React escapes text content by default; no `dangerouslySetInnerHTML` used anywhere.
- **Repository:** Local git, GitHub remote (`origin`). Task branches pushed individually (e.g. `feature/01-setup`) rather than committing to `main`. **Relevant for Task 19:** confirm which branch(es) the CI workflow should trigger on (`main`, all branches, or PRs specifically) — not yet decided, see Open Questions.

- **Bookmark Validation Pattern:** "At least one of X or Y required" via `pre('validate')` + `this.invalidate()`, not per-field `required` functions (Task 05). Mirrored client-side in `AddBookmarkForm.jsx`.
- **Bookmark Defaults:** `collection` defaults to `'Uncategorized'`.
- **Route-Specific Middleware Without Editing Route Files:** Exact-path `app.METHOD(path, ...middleware)` registered before the router's `app.use(prefix, router)` mount, when a task's target files exclude the router file itself (Task 08 pattern, reusable).
- **Frontend Build Tool:** Vite (`react` template, ESLint) (Task 11).
- **Frontend HTTP Client:** Native `fetch` via hand-written `apiClient` (`frontend/src/api/client.js`), not axios. `credentials: 'include'` on every request. As of Task 15, `request()` attaches `err.status = res.status` to every thrown error — callers branch on `.status` (`404`, `409`, `429`) instead of string-matching `.message`.
- **Frontend Routing:** `react-router-dom`, `BrowserRouter`/`Routes` in `App.jsx`, extended with `/login`, `/register`, `ProtectedRoute`-guarded `/`, wrapped in `AuthProvider` then `ToastProvider`.
- **Frontend Env Vars:** `frontend/.env` uses `VITE_` prefix — `VITE_API_BASE_URL` (Task 11). `frontend/.env.example` added Task 18.

Auth endpoints and single-bookmark endpoints (`getBookmark`, `updateBookmark`, `createBookmark`) return flat objects, consumed directly. List endpoints wrap in `{ data: [...] }` — callers (`BookmarkList.jsx`) unwrap `.data` explicitly.
- **Backend Env Loading:** `backend/server.js` must call `require('dotenv').config()` as its first line, before `validateEnv()`. `config/env.js` exports `{ validateEnv }` (named export) — canonical style, keep consistent if `env.js` is touched again.
- **Frontend Auth State:** `AuthContext.jsx` exports `AuthProvider` (`user`, `loading`, checks `/api/auth/me` on mount) and `useAuth()` exposing `{ user, loading, login, register, logout }`. No separate `/me` refetch after login/register — state set directly from the response.
- **Frontend Route Guarding:** `ProtectedRoute.jsx` — layout route using `<Outlet />`, shows loading while the initial `/me` check is in flight, redirects to `/login` via `<Navigate replace>` if no user.
- **Page Component Location:** Route-level pages (`Login.jsx`, `Register.jsx`, `Home.jsx`) in `frontend/src/pages/`. Reusable UI (`Toast.jsx`, `BookmarkCard.jsx`, `BookmarkList.jsx`, `EditBookmarkModal.jsx`, `SearchBar.jsx`, `TagPills.jsx`, `AddBookmarkForm.jsx`) in `frontend/src/components/`.
- **Bookmark List Component Structure:** `BookmarkList.jsx` owns fetch/pagination state, edit/delete handlers, search/tag filter state, and an imperative `addBookmark` method via `forwardRef`/`useImperativeHandle`. Renders `BookmarkCard`s from `filteredBookmarks`, not raw `bookmarks`. As of Task 18, also renders one of two empty-state messages when `filteredBookmarks`/`bookmarks` is empty.
- **Delete Confirmation Pattern:** Native `window.confirm()`, not a custom modal (Task 15).
- **Error Status Codes on the Frontend:** `apiClient`'s `request()` sets `err.status = res.status`. Convention: check `err.status === 404` for "resource no longer exists," `err.status === 429` for rate-limit messaging, before falling back to generic `err.message`.
- **Styling (Task 18):** Plain hand-written CSS in `frontend/src/App.css` — no CSS framework/utility library installed. New rules (`.form-field`, `.bookmark-card`, `.empty-state`, `.toast-*`, focus-visible outlines) reuse existing theme variables from `frontend/src/index.css` (`--text`, `--text-h`, `--border`, `--bg`, `--accent`) rather than introducing separate hardcoded color variables, so the existing `prefers-color-scheme: dark` block continues to theme the new UI correctly. Toast status colors (`success`/`error`) are intentionally fixed hex values, not theme-linked, since status colors conventionally don't shift with dark mode.
- **CORS Origin Handling (Task 18):** `CLIENT_ORIGIN` env var supports a comma-separated list of allowed origins, parsed once at module load into an `allowedOrigins` array in `backend/middleware/security.js`. `cors()`'s `origin` option is a callback (not a static string/array) that checks membership and allows requests with no `Origin` header through unconditionally.
- **CI Pipeline (Task 19):** Automated via GitHub Actions in `.github/workflows/ci.yml`. Runs backend integration tests (`jest --runInBand` via `npm test`) on `ubuntu-latest` against Node 20.x and 22.x LTS versions, caching npm dependencies via `backend/package-lock.json`. Triggers on push (`main`, `feature/**`) and PRs to `main`. Includes a companion `frontend-build` smoke test (`npm ci && npm run build` on Node 22). Relies on `mongodb-memory-server` with `MONGOMS_MD5_CHECK=0` and provides fallback `JWT_SECRET` in both workflow env and `tests/setup.js`.
- **Password Reset Security (Task 20):** Tokens generated via `crypto.randomBytes(32)` (64-char hex string). Raw token is passed only in the reset URL; database stores only a SHA-256 hash (`crypto.createHash('sha256')`) with a 15-minute expiration time (`resetPasswordExpire`) to protect against token leakage in case of database dumps.
- **Email Delivery Strategy (Task 20):** Handled by `backend/services/emailService.js` via `nodemailer`. In test mode (`NODE_ENV === 'test'`), email calls are mocked without network latency. In local dev, uses an auto-generated Ethereal test inbox or logs the reset link to console. In production, connects via standard SMTP (`SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `EMAIL_FROM`).
- **Anti-Enumeration (Task 20):** `POST /api/auth/forgot-password` returns a consistent 200 status with generic message whether or not an account exists with the requested email address.
- **Rate Limiting on Password Resets (Task 20):** Dedicated `passwordResetLimiter` (5 attempts per 15 minutes per IP) protects `/api/auth/forgot-password` from abuse and email spamming.
- **Frontend Component Testing (Task 21):** Vitest + React Testing Library + @testing-library/jest-dom + @testing-library/user-event + jsdom. Tests are co-located in `frontend/src/components/__tests__/`. Polyfills for JSDOM (`ResizeObserver`, `IntersectionObserver`, `window.scrollTo`) are centralized in `frontend/src/test/setup.ts`. `frontend/.npmrc` sets `legacy-peer-deps=true` to guarantee deterministic npm dependency resolution across local and CI environments. CI runs `npm test` before `npm run build` in GitHub Actions.
